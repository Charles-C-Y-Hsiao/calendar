## Daily dialog extraction and Account guard

- `shared/user-account/account-user-dialog.js` now centralizes Daily user-dialog interaction: opening from `#show-user-name`, close/overlay handling, current-id prefill, counter, clear, keyboard actions and dispatch to `accountLoginAdapter`.
- `daily-account-adapter.js` keeps Daily-specific behavior (`getCurrentUserId()` and `onLoginSuccess()` ??`applyUserIdFromDialog()`), so storage, links, WebSocket and data reload semantics are unchanged.
- `shared/user-account/account-dialog.css` also supplies the Account guard palette. `openDeleteAllUserCheckDialogV2()` retains its current-id verification and final confirmation; only presentation is shared. `openDeleteAllUserCheckDialog()` currently has no caller and is recorded as legacy.

## Shared action dialogs

- `shared/action-dialogs/module.js` provides `actionDialogs.alert()` and `actionDialogs.confirm()`.
- `shared/action-dialogs/module.css` owns the common overlay, dialog surface, buttons and alert presentation. Daily confirmation dialogs and Monthly `dt-dialog` panels use these primitives.
- Monthly `edit_time_dialog()` and `openDayPanel()` remain in `monthly-calendar/monthly-day-panel.js` because they own date/task state and persistence callbacks; only their shell and validation notices are shared.
- Monthly `monthly-day-panel.css` no longer defines the generic `.dt-dialog` shell; those dimensions, shadow and overlay rules now come from `shared/action-dialogs/module.css`, which is also loaded by Daily.
- `module.css` also owns confirm button classes (`.action-confirm-ok` / `.action-confirm-cancel`); Monthly `.dt-dialog-actions` remains only for Monthly-specific markup.
